# LOCOMgcm and MITgcm, case by case

LOCOMgcm implements the discretizations of MITgcm. What it covers is stated
here through the cases in which it has been run beside MITgcm and compared
with it. There are three sets of cases.

| Set | Cases compared with MITgcm | Agree with MITgcm |
|---|---|---|
| [South China Sea configurations](#south-china-sea-configurations) | one regional configuration at three resolutions: a 29-day run and gradients | fields within the spread of MITgcm runs that differ in process layout |
| [MITgcm verification experiments](#mitgcm-verification-experiments) | 22 experiments run from their own MITgcm namelists | 22 |
| [Generated combinations](#generated-combinations) | 229 cases that vary about 50 options on 8 base configurations | 183 |

Below the cases, [Options at a glance](#options-at-a-glance) lists what
LOCOMgcm has and lacks by area, and the [option reference](#option-reference)
gives the status of every MITgcm option and package.

## South China Sea configurations

`experiments/configs/cases/scs_paper_h160.yaml`, `scs_paper_h480.yaml` and
`scs_paper_h960.yaml` are one regional configuration of the South China Sea
and the western Pacific at three resolutions, the finest 1/32° (960 × 912 ×
90 cells). It uses a spherical-polar grid with partial cells, the hydrostatic
equations, the implicit linear free surface, staggered time stepping,
vector-invariant momentum, Leith and Smagorinsky viscosity, KPP, the JMD95P
equation of state, linear and quadratic bottom drag, and open boundaries with
prescribed values, flow balancing and sponge layers. Initial and boundary
values come from HYCOM, the surface forcing from ERA5.

- Forward run: over 29 days at 1/32°, the temperature of LOCOMgcm differs from
  that of MITgcm by about as much as two MITgcm runs with different process
  layouts differ from each other (figure in the README).
- Gradient: compared with the MITgcm adjoint generated by Tapenade, built from
  `verification/adjoint/scs_h`.

With `mit_comparison.enabled: true` in the case file, the pipeline prepares
the MITgcm run directory of the same configuration, runs both models and
compares them.

## Generated combinations

A verification experiment fixes one combination of options. To cover the
combinations, cases are generated from 8 base configurations: each case sets
about 50 options, and the set of cases is chosen so that every two option
values that can be used together occur together in at least one case. 229 of
the cases can be expressed in MITgcm. They are run in both models and
compared, and 183 agree.

| Base configuration | Compared with MITgcm | Agree |
|---|---|---|
| South China Sea, 160 × 152 × 90 | 53 | 49 |
| tutorial_deep_convection | 41 | 24 |
| tutorial_baroclinic_gyre | 31 | 25 |
| tutorial_global_oce_latlon | 27 | 22 |
| tutorial_barotropic_gyre | 23 | 18 |
| internal_wave | 22 | 18 |
| offline_exf_seaice | 16 | 15 |
| vermix | 16 | 12 |
| Total | 229 | 183 |

A case agrees when u, v, temperature, salinity and eta match MITgcm at every
compared step, when its gradient is within a relative 1e-8 of the MITgcm
adjoint in double precision (1e-3 in single precision), and when a restarted
run reproduces the uninterrupted one bit for bit. Of the 46 other cases, 40
have no MITgcm result to compare with (for example a gradient case for which
no verified MITgcm adjoint exists), 2 depart from MITgcm through rounding
that an ill-conditioned step amplifies in both models, in 1 MITgcm itself
diverges, 1 did not finish, in 1 the pressure solve of the gradient run did
not converge, and 1 differs from MITgcm.

# Option reference

The MITgcm side of the reference follows the source at commit `d861cd50` and
the organisation of the MITgcm manual. The LOCOMgcm side was read from the
code: an entry is marked from the implementation that a time step reaches and
from the checks that refuse a configuration when the model is built.

## How to read the tables

Status:

- `yes`: implemented and selectable from a case file, or from the Python API
  where the row says so.
- `partial`: implemented with the restriction given in the last column.
- `no`: not implemented. Selecting it stops the model build with an error, or
  there is no way to select it.
- `n/a`: the package serves the Fortran build or an AD tool and has no
  counterpart in a PyTorch program.

Selectors refer to the case file (`experiments/configs/cases/*.yaml`, described
in [USAGE.md](USAGE.md)):

- `stepper.X` is the field `X` under `model.stepper.kwargs` of the
  `implicit_free_surface` stepper.
- `dyn[name].X` is the field `X` of the entry `name` in `model.dynamics`.
- `grid.X`, `time.X`, `physics.X`, `advection.X`, `boundary.X`, `run.X`,
  `sources.X` and `case.extras.X` are blocks of the case file.

"Lat-lon" means the Cartesian and spherical-polar grids, as opposed to the
cubed sphere. "Rank" means one process of a multi-GPU or multi-CPU run. "The
translator" is `experiments/mitcases/translate.py`, which converts the
namelists of a MITgcm verification case into a case file.

Options that exist only in LOCOMgcm are not listed.

### Restrictions that cut across the tables

Most restrictions are in the rows above. The ones that involve several tables
are collected here.

- Cubed sphere. Six square faces, closed global domain, the
  `implicit_free_surface` stepper. Linear free surface; hydrostatic;
  vector-invariant momentum with vorticity scheme 1 or 4; constant harmonic
  viscosity in the divergence-vorticity form; bottom drag; tracer advection
  scheme 1 or 33 with harmonic diffusion; JMD95Z; one time step for momentum,
  tracers, free surface and clock. Not available on the cubed sphere: real
  freshwater flux, implicit vertical advection, `ivdc_kappa`, convective
  adjustment, PP81, MY82, GGL90, KL10, GM/Redi, EXF, `allowFreezing`,
  `pLoadFile`, the CD scheme.
- Nonlinear free surface (`nonlinFreeSurf` 1 to 3). Hydrostatic, with
  `exactConserv` (both as in MITgcm). Not with a Flather boundary, not with
  `linFSConserveTr` (as in MITgcm), not with a wet column shallower than the
  top layer, not with EXF climatology relaxation.
- z\* (`select_rStar=2`, `nonlinFreeSurf=4`). Tracers in a prescribed flow
  only (`momStepping=.FALSE.`). Not with real freshwater flux, KPP, implicit
  vertical advection, the non-hydrostatic solver, open boundaries or the cubed
  sphere.
- Non-hydrostatic. `implicSurfPress = implicDiv2DFlow = 1`, linear free
  surface, lat-lon grids. Not with Orlanski boundaries, PP81, MY82, GGL90 or
  KL10.
- Implicit vertical advection of tracers. Staggered time stepping, lat-lon
  grids, vertical schemes 1, 2, 3, 20, 30 and 33.
- Dynamic-pressure equations of state (JMD95P, MDJWF with pressure from the
  model). Lat-lon grids; not with `pLoadFile`.

## Derivatives

MITgcm obtains its adjoint and tangent-linear code from TAF, Tapenade or
OpenAD. LOCOMgcm is a PyTorch program, and PyTorch differentiates the time
step that ran.

| Capability | Notes |
|---|---|
| Reverse mode through the time step | Run with `track_gradients=True`, then call `torch.autograd.grad` or `backward`. |
| Checkpointing with recomputation | A window (`locomgcm/checkpoint`) stores the state at the head of each segment and replays the segments in reverse. First-order derivatives only. |
| Forward mode | `torch.autograd.forward_ad` dual tensors. One rank, not compiled, not inside a checkpoint window. |
| Pressure solves (CG2D, CG3D) | Differentiated with the implicit-function rule at the cost of one more solve; the first guess and the preconditioner carry no derivative. Differentiating the iterations themselves is an option. |
| Implicit vertical solves | Analytic adjoint and tangent of the tridiagonal and banded systems. |
| Nonlinear free surface | The dependence of the cell thickness factors on the surface elevation is kept. |
| Several ranks | First-order reverse mode in double precision. |
| Neural networks inside the time step | A network can replace the KPP diagnosis or the bottom-drag law, and its weights are trained through the time step (`locomgcm/learned`, Python API). |

Derivatives can be taken with respect to the initial eta, u, v, temperature
and salinity, to network weights, and to any tensor of a module that is bound
as a parameter, for example the bottom-drag coefficient or forcing records
such as wind stress and heat flux. The reference temperature and salinity
profiles computed from the initial state when the model is built carry no
derivative.

| MITgcm package | In LOCOMgcm |
|---|---|
| autodiff, tapenade, openad | PyTorch autograd; checkpoint windows take the place of the store directives. |
| admtlm | No singular-vector driver. |
| ctrl | No control-vector files, weights or packing; a control is a tensor. |
| cost | No cost package; the objective is a Python function of the model state. |
| grdchk | No package; a finite-difference check is written in Python. |
| ecco, profiles, obsfit, smooth | Absent. |

The MITgcm adjoint builds used for the gradient comparisons are in
`verification/adjoint/`.

## Parallelism and hardware

| Topic | LOCOMgcm |
|---|---|
| Device | `run.device: cuda`, `cpu` or `auto`. |
| Precision | `run.precision: float64` (default) or `float32`. |
| Several ranks, lat-lon grids | Horizontal decomposition into `nPx` by `nPy` subdomains, one per rank; the subdomains may differ in size. |
| Several ranks, cubed sphere | Whole faces per rank: 1, 2, 3 or 6 ranks. |
| Communication | NCCL between GPUs, Gloo between CPU processes; launched with `torchrun` or under SLURM. |
| Halo exchange | Point-to-point exchange between neighbouring ranks; global sums are reduced in a fixed order. |
| Compilation | `torch.compile` of the tendency or of the whole time step (`LOCOMGCM_COMPILE_TARGET`). |
| Native CUDA kernels | Optional kernels for the equation of state, KPP, tridiagonal solves, implicit vertical advection, tracer advection, vector-invariant momentum, Leith/Smagorinsky viscosity and the CG2D/CG3D solvers; the switches are listed in [USAGE.md](USAGE.md). |

MITgcm tiles (`sNx`, `sNy`, `nSx`, `nSy`) and threads have no counterpart.
Forward-mode derivatives, the sea-ice module and compilation with dynamic
shapes run on one rank only.

## Input, output and restart

| Topic | LOCOMgcm |
|---|---|
| What defines a run | A case file, run by the pipeline or from Python. The model does not read a MITgcm run directory. |
| From MITgcm namelists | `experiments/mitcases/translate.py` converts a verification case (`input/data*`, `code/SIZE.h`, `code/*_OPTIONS.h`) into a case file. It stops at any namelist entry it has no rule for. It covers fewer options than the model: for example it does not convert `useAbsVorticity`, `useStrainTensionVisc`, different advection schemes for temperature and salinity, OBCS sponges or the cubed sphere. |
| Input formats | MITgcm big-endian binaries, 32 or 64 bit (initial conditions, bathymetry, forcing, OBCS and EXF files); MDS `.meta`/`.data`; NetCDF (HYCOM, ERA5, GEBCO, TPXO9); zarr; analytic fields. |
| Start from a MITgcm pickup | `initial_condition.mit_pickup`. One global double-precision pickup with a field list, and `pickup_cd`. Lat-lon grids, hydrostatic, linear free surface, no real freshwater flux. |
| Output | NetCDF snapshots of eta, temperature, salinity, u, v and w at a fixed interval; station columns; monitor lines. |
| Restart | LOCOMgcm checkpoints (`checkpoint:` block) holding the state and the time-stepping history in double precision. |
| MITgcm-format output | None from the ocean model: no MDS or MNC fields, no ocean pickups, no `diagnostics` output. |
| Writing a MITgcm run directory | With `mit_comparison.enabled: true` the pipeline writes `SIZE.h`, the `data*` namelists, the option headers and the binary input files of the case, so that MITgcm can run the same configuration. |
